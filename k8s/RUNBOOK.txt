Kubernetes  dev/stage и данные
Docker-контейнеры Terraform остаются отдельной системой. Здесь свой kind-кластер, один control-plane на том же хосте. Не создавайте поверх существующего одноимённого кластера: kind get clusters и docker inspect dva-course-control-plane сначала.
kind create cluster --name dva-course --config k8s/kind.yaml./lab guard --bind./lab guardkubectl --context kind-dva-course apply -f k8s/namespaces.yamldocker build -t dva-ticket:advanced-m04 ticket-labdocker image inspect dva-ticket:advanced-m04 --format '{{.Id}} {{.Architecture}}'kind load docker-image dva-ticket:advanced-m04 --name dva-course
Сохранить UID dev/stage, IP/порт API server и image ID без вывода env. guard сохраняет идентичность в .runtime/cluster-id.json и откажет для другого UID. Скрипт привязки не заменяет осмотр владельца первого кластера.
Для каждого ns dev и stage выполнить следующую последовательность, меняя ns=dev на ns=stage. Shell-переменная не является системной:
ns=dev./lab guard./lab secrets "$ns"kubectl --context kind-dva-course -n "$ns" apply -f k8s/db.yamlkubectl --context kind-dva-course -n "$ns" rollout status statefulset/postgres --timeout=120skubectl --context kind-dva-course -n "$ns" apply -f k8s/init-job.yamlkubectl --context kind-dva-course -n "$ns" wait --for=condition=complete job/init-db-m04 --timeout=150skubectl --context kind-dva-course -n "$ns" apply -f k8s/migrate-job.yamlkubectl --context kind-dva-course -n "$ns" wait --for=condition=complete job/migrate-m04 --timeout=150skubectl --context kind-dva-course -n "$ns" apply -f k8s/app.yamlkubectl --context kind-dva-course -n "$ns" rollout status deployment/ticket-api --timeout=120s
Job ошиблась: сначала describe job, logs job/<имя> (проверить, нет ли секретов в выводе), причина и исправление. Не переходить к API после неуспешной миграции. Для повторения изменившейся Job удалить только её по точному имени после сохранения журнала; pod template Job immutable. prepare_secrets отказывает, если хотя бы один Secret уже существует: неполное создание восстановить отдельно после выяснения, не затирать рабочие пароли.
Публикация Service через заранее проброшенные NodePorts:
kubectl --context kind-dva-course -n dev patch service ticket-api --type merge -p '{"spec":{"type":"NodePort","ports":[{"name":"http","port":8000,"targetPort":"http","nodePort":30220}]}}'kubectl --context kind-dva-course -n stage patch service ticket-api --type merge -p '{"spec":{"type":"NodePort","ports":[{"name":"http","port":8000,"targetPort":"http","nodePort":30230}]}}'./lab http --base http://127.0.0.1:18220 --out evidence/m04-dev.json./lab http --base http://127.0.0.1:18230 --out evidence/m04-stage.json
Сохранить created_ticket из отчёта как .runtime/old-ticket.json, его числовой id записать в свою переменную old_id. Пример извлечения для stage:
python3 -c 'import json,pathlib; r=json.load(open("evidence/m04-stage.json")); pathlib.Path(".runtime/old-ticket.json").write_text(json.dumps(r["created_ticket"]))'old_id=$(python3 -c 'import json; print(json.load(open(".runtime/old-ticket.json"))["id"])')
Пересоздать только один API Pod: сначала get pods -l app=ticket-api, затем delete pod <выбранное имя>. Service остаётся тем же, Deployment создаёт новый Pod. После rollout повторить HTTP со --read-id "$old_id" --expected .runtime/old-ticket.json --out evidence/m04-pod-recovery.json.
Для probe-эксперимента сохранить deployment YAML локально; изменить путь readiness у контейнера api на /missing, не меняя liveness. Посмотреть ready count, events, endpoints и доступность Service; maxUnavailable/Surge определяют, остаются ли старые Pods. Вернуть /ready, дождаться rollout и полезной операции. Не заявлять заранее полный outage: результат зависит от стратегии и старых Pods. /health не зависит от БД, /ready делает SQL.
Пересоздать postgres-0 без удаления PVC, дождаться StatefulSet и API; сравнить прежний id/title/status и UID PVC до/после. У dev и stage разные PVC UID. PVC одного kind-хоста не подтверждает защиту от потери хоста. Requests помогают scheduling, CPU limit ограничивает CPU, memory limit может дать OOMKilled; сравнивать last state/events, а не только Running. Probes.
