Проверить и разрешённое, и запрещённое

Все команды из корня ~/advanced-lab, кроме явно указанного cd.

kubectl --context kind-dva-course apply -f security/stage-reader.yaml
kubectl --context kind-dva-course auth can-i get pods -n stage --as=system:serviceaccount:stage:ticket-reader
kubectl --context kind-dva-course auth can-i get secrets -n dev --as=system:serviceaccount:stage:ticket-reader
kubectl --context kind-dva-course -n stage scale deployment ticket-api --replicas=0
kubectl --context kind-dva-course -n stage rollout status deployment/ticket-api --timeout=120s
./lab db-role create --namespace stage
kubectl --context kind-dva-course -n stage scale deployment ticket-api --replicas=2
kubectl --context kind-dva-course -n stage rollout status deployment/ticket-api --timeout=120s

Reader должен читать stage Pods и не читать Secrets/соседние dev Pods. Для create runtime-роли все API-writers предварительно остановлены; повторное create существующей роли не нужно. Для смены пароля используется ./lab db-role rotate --namespace stage, тоже при остановленных writers. После возврата проверяются старый GET и новый POST/PATCH. Runtime-роль не должна менять схему или удалять таблицу. Учебный Kubernetes Secret хранит base64, но это не шифрование. Vault рассматривается как отдельная архитектура; работающего Vault-сервера в обязательном комплекте нет.

Остановка при ошибке: запишите ненулевой exit code и последнее успешное наблюдение. Проверьте цель и причину, исправьте один фактор, повторите операцию новым именем evidence. Не удаляйте данные ради зелёного результата.
Дополнительные эксперименты и критерии каждого урока приведены в Stepik; общая подготовка выше выполняется один раз, а не повторно на каждом уроке.
