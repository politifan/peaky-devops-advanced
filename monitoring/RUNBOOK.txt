Метрики, панели и сигнал отказа
API текущего advanced образа имеет /metrics: счётчик запросов, histogram длительности, readiness gauge. /health, /ready и /metrics исключены из пользовательского HTTP counter. Endpoint без авторизации доступен внутри учебной сети; не публиковать его в интернет.

Создать трафик несколькими запусками ops/http_check с уникальными именами out; подождать минимум две scrape и минутное окно rate. В Targets должны быть отдельные API Pods обоих ns, а не один Service endpoint. Labels route имеют шаблон /tickets/{ticket_id}, не конкретные id. Requests POST/GET/PATCH дают разные method/status, разбираются отдельно.
sum by (namespace) (rate(ticket_http_requests_total[1m]))sum by (namespace) (rate(ticket_http_requests_total{status=~"5.."}[1m])) / sum by (namespace) (rate(ticket_http_requests_total[1m]))histogram_quantile(0.95, sum by (namespace, le) (rate(ticket_http_request_duration_seconds_bucket{status=~"2.."}[1m])))sum by (namespace) (ticket_ready)
Пустой denominator означает NoData, не 100% успешность. Histogram p95 — оценка по buckets, не точная клиентская квантиль. Counter сбрасывается при restart, rate учитывает наблюдаемые сбросы. Transport failure до API отсутствует в серверном counter: для SLO нужен также клиентский журнал попыток.
Отказ и восстановление
Сохранить старую stage запись; убедиться, что в dev HTTP работает. Масштабировать только statefulset/postgres stage до 0. Дождаться исчезновения Pod, наблюдать /ready и dashboard. API /health остаётся живым, метрики могут собираться, но ticket_ready становится 0. NodePort без готовых endpoints может дать transport failure, а не 503.
После первого наблюдения условия alert ждёт 30s for, плюс задержка scrape/evaluation. Сохранить время отказа, pending, firing из Prometheus Alerts. Нет Alertmanager/внешней доставки: firing в UI не означает отправку сообщения. Вернуть stage postgres до 1, дождаться rollout и API готовности, выполнить HTTP со старым id/expected, увидеть resolved. Сохранить dev-операцию во время stage отказа.
Логи API: kubectl --context kind-dva-course -n stage logs deployment/ticket-api --tail=100; при нескольких Pods собрать каждый отдельно. Структурированные строки связывают request_id/route/status/duration; тело и query не пишутся. Не отправлять Secret/env в общий журнал. Prometheus/Grafana используют emptyDir, после пересоздания их Pods история теряется — это учебная наблюдаемость, не долговечное хранилище. Конфигурация Prometheus, alert rules.
