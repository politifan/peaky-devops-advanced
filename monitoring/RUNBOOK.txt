Привязать сигнал к реальному отказу

Все команды из корня ~/advanced-lab, кроме явно указанного cd.

./lab monitoring-admin
kubectl --context kind-dva-course apply -f monitoring/rbac.json
kubectl --context kind-dva-course apply -f monitoring/stack.json
kubectl --context kind-dva-course -n monitoring rollout status deployment/prometheus --timeout=180s
kubectl --context kind-dva-course -n monitoring exec deployment/prometheus -- promtool check config /etc/prometheus/prometheus.yml
kubectl --context kind-dva-course -n monitoring exec deployment/prometheus -- promtool check rules /etc/prometheus/rules.yml
kubectl --context kind-dva-course -n monitoring port-forward service/prometheus 19090:9090

Port-forward занимает отдельный терминал; Ctrl+C завершает только туннель. Откройте http://127.0.0.1:19090/targets, проверьте scrape dev/stage, затем /alerts. ReadinessLost имеет for: дождитесь pending, затем firing; после возврата проследите снятие. Отсутствие target не равно нулю ошибок. Grafana доступна отдельным туннелем к service/grafana 13000:3000; логин admin, пароль в .runtime/grafana-admin.txt. Не вставляйте пароль в отчёт. Подключите dashboard monitoring/dashboard.json; сначала источник данных Prometheus http://prometheus:9090.

Остановка при ошибке: запишите ненулевой exit code и последнее успешное наблюдение. Проверьте цель и причину, исправьте один фактор, повторите операцию новым именем evidence. Не удаляйте данные ради зелёного результата.
Дополнительные эксперименты и критерии каждого урока приведены в Stepik; общая подготовка выше выполняется один раз, а не повторно на каждом уроке.
