Восстановить в новую цель и прочитать прежние поля

Все команды из корня ~/advanced-lab, кроме явно указанного cd.

kubectl --context kind-dva-course -n stage scale deployment ticket-api --replicas=0
kubectl --context kind-dva-course -n stage rollout status deployment/ticket-api --timeout=120s
./lab backup --namespace stage --other-writers-stopped
./lab restore backups/YOUR_FOLDER --destination restore-20261009000100
kubectl --context kind-dva-course -n restore-20261009000100 port-forward service/ticket-api 18400:8000
# В другом терминале:
./lab http --base http://127.0.0.1:18400 --read-id YOUR_ID --expected evidence/old-ticket.json --out evidence/restored-http.json

До остановки сохраните старую заявку JSON в evidence/old-ticket.json и её ID. YOUR_FOLDER/YOUR_ID подставляются из вашего запуска; destination — новое имя с 14 цифрами, не занятое ранее. Подтверждение other-writers-stopped имеет смысл только после остановки нагрузки, миграций и остальных writers. Backup сравнивает полный снимок и checksum, restore — SQL-состояние в новом namespace. Restore-report без HTTP ещё не закрывает приёмку: нужен старый GET с ожидаемыми полями и полезная новая операция. После копии/проверки верните stage replicas=2 и проверьте rollout. Измерьте собственные RPO/RTO с указанной начальной и конечной точкой.

Остановка при ошибке: запишите ненулевой exit code и последнее успешное наблюдение. Проверьте цель и причину, исправьте один фактор, повторите операцию новым именем evidence. Не удаляйте данные ради зелёного результата.
Дополнительные эксперименты и критерии каждого урока приведены в Stepik; общая подготовка выше выполняется один раз, а не повторно на каждом уроке.
