Отдать управление API Helm, сохранив БД

Все команды из корня ~/advanced-lab, кроме явно указанного cd.

helm lint chart
helm template ticket-api chart -n stage -f chart/values-stage.yaml > evidence/rendered-stage.yaml
kubectl --context kind-dva-course -n stage get deployment/ticket-api service/ticket-api
kubectl --context kind-dva-course -n stage delete deployment/ticket-api service/ticket-api
helm --kube-context kind-dva-course upgrade --install ticket-api chart -n stage -f chart/values-stage.yaml --atomic --wait --timeout 180s
helm --kube-context kind-dva-course -n stage history ticket-api
./lab http --base http://127.0.0.1:18230 --out evidence/helm-stage.json

Переход от kubectl к Helm выполняется один раз в своей учебной stage: сохраните прежний ID, проверьте render и удалите только два перечисленных API-объекта. Это краткая учебная пауза, а не миграция без простоя. ServiceAccount ticket-runtime, БД, Jobs и PVC остаются. Не применяйте delete --all. Иначе Helm встретит конфликт ownership. После установки сравните прежнюю запись. Затем испытайте неверный probes.readinessPath=/not-ready с --atomic --wait --timeout 45s: ожидается ненулевой код, возврат прежней версии и прежние данные. Rollback приложения не откатывает SQL-схему.

Остановка при ошибке: запишите ненулевой exit code и последнее успешное наблюдение. Проверьте цель и причину, исправьте один фактор, повторите операцию новым именем evidence. Не удаляйте данные ради зелёного результата.
Дополнительные эксперименты и критерии каждого урока приведены в Stepik; общая подготовка выше выполняется один раз, а не повторно на каждом уроке.
